# AI-native 功能实现与验收

版本日期：2026-10-13。此版本面向 Agent 工程与 AI-native Builder 两类岗位，提供可运行交互和业务机制的验证证据。

## 已实现的关键设计

1. **需求提案与业务事务**：`requirement_contracts.py` 接收有类型的变更操作，记录原文与来源。模型不能通过自报 `explicit` 获得修改权限；确定性解析无法独立确认的操作进入待确认提案。自然语言和卡片均经同一事务执行，卡片附带 `expected_revision`，过期编辑返回 409。
2. **短事务与长任务分离**：会话锁仅保护入口更新和提交；检索在锁外执行。SQLite 发布事务同时比较需求版本、消息轮次和选择版本。条件没变化但用户发起新确认，也不会被旧工具结果覆盖。线程工具无法强制取消，过期输出被丢弃。
3. **有界条件协商**：无匹配时，从完整住宿区间的有效库存求最小可行预算；日期仅在用户授权灵活调整时检查前后一天，保留非支配方案。最多一次宽预算查询和三次方案查询。接受方案后重新查询，提案不能直接当作房源承诺。
4. **证据约束推荐**：安静、亲子与地铁步行时间保存来源、核验状态、观察时间与过期时间。未知与不满足分别处理；必需偏好未知时进入人工核验。先对完整业务候选进行证据过滤，再截取展示结果，避免 Top-K 提前漏掉符合必需偏好的酒店。
5. **单问题追问**：按业务顺序选择一个阻塞条件，优先处理错误，然后依次补充城市、日期、预算和房型。当前是确定性策略，尚未实现学习型信息增益策略。
6. **可恢复人工审批**：选定酒店后建立独立 LangGraph 审批图，通过真实 `interrupt` 暂停。审批需要独立令牌，绑定需求版本、选择版本和报价有效期；恢复前重新查询报价和必需偏好证据。审批生成唯一交接回执，重复审批复用回执；不创建供应商订单、不执行支付。

## 产品交互

启动 `python demo_web.py --redis-simulated`，打开 `http://127.0.0.1:8765`。

- 自然语言补全条件，或直接编辑右侧条件卡片。
- 输入“预算改成100元”，查看可选方案，点击接受后再检索。
- 输入“希望安静，带孩子，步行10分钟内到地铁”，查看证据来源与未知提示。
- 选定酒店，输入审批人及本地演示令牌 `demo-reviewer`，点击人工确认。
- 审批前修改日期、修改选择、更新库存价格或使证据过期，旧草稿均不能通过。
- SSE 推送当前状态与轨迹；界面允许检索期间继续发送修改，丢弃过期响应。

HTTP 接口：`/api/chat`、`/api/requirements/commit`、`/api/requirements/accept`、`/api/relaxations/accept`、`/api/drafts/approve`、`/api/events`。完整请求结构可在启动后的 `/docs` 查看。审批令牌使用 `X-Reviewer-Token` 请求头；生产配置 `REVIEWER_TOKEN`，没有默认生产令牌。

## 可复现验证

```powershell
python -m pytest -q
python scripts/evaluate_ai_native.py
python scripts/capture_demo.py --channel msedge
```

轨迹报告：[evaluation-results.json](evaluation-results.json)。包含 60 条合成确定性业务轨迹，六类各十条：否定与日期保持、住宿总预算、卡片版本冲突、条件协商、未知事实、人工审批。它们覆盖端到端服务与实际检查点机制，未调用模型，不代表语言准确率；模型实验 A/B 与真实供应商核验仍待完成。真实模型接口连接检查遇到 `APIConnectionError`，本次未验证其响应。

浏览器通过系统 Edge 真实操作，验证 11 次业务响应并生成 9 张截图。截图使用真实目录名、合成库存与合成酒店事实，页面和证据来源均明确标注。

## 设计取舍与修复记录

- **模型权限**：原文子串只能证明文本出现过，不能证明模型理解正确，因此独立规则无法验证的模型操作统一要求确认。
- **双版本不足**：只检查需求版本会漏掉“预算稍微高一点”这类尚未提交的提案，加入消息轮次后拒绝同条件版本下的旧输出。
- **审批与展示分离**：工作台展示草稿，独立审批图保存中断；避免普通对话自动恢复写操作。
- **兼容性修复**：本机 Python 3.9 的执行线程不自动传播 LangGraph runnable context，审批节点显式使用框架传入的 config 建立上下文。通过真实中断、重启和恢复测试验证。
- **报价变化**：仅依赖 TTL 不能发现有效期内价格更新，审批重新计算报价签名并核验必需偏好证据。
- **持久层权威**：Redis 是缓存；状态提交、版本判断、请求去重和审批回执以 SQLite 为准。

## 当前边界

单进程 MVP；没有多实例任务租约、用户登录及生产角色权限系统。演示审批令牌不是生产认证方案。没有供应商订单接口、支付、学习型追问策略或模型质量对比结果。报价有效期与核验事实仍需要供应商数据源保证；公开数据只用于机制演示。
