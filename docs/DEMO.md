# YF-Agent 项目展示指南

## 展示前准备

- 安装依赖与 Playwright Chromium，准备基础模型及微调分类权重。
- 配置 `.env`，验证模型接口可用。
- 从 `data/hotels.xlsx` 选取完整门店名，试跑常规咨询与工具查价。
- 遮盖真实用户信息、账号标识与凭据，关闭包含敏感配置的窗口。

## 约 5 分钟的展示顺序

### 第 1 分钟：业务问题

“酒店客服经常面对重复咨询、日期与门店信息不完整、实时价格需要人工查找等问题。这个项目把闲鱼消息接入、意图识别和酒店查价组织成可观察的 Agent 工作流。”

说明当前属于工程原型：查询与预订沟通已实现，真实自动下单和支付尚未接入。

### 第 2 分钟：架构

打开 README 架构图，说明三层职责：

1. 接入：WebSocket、消息过滤、人工接管。
2. 决策：本地 BGE-M3 分类、LangGraph 路由、提示词准备。
3. 执行：模型工具调用、Playwright 采集、SQLite / Excel 存储。

讲解设计取舍：分类在本地执行；回复由模型服务生成；工具提供实时数据；历史消息为后续问题提供上下文。

### 第 3～4 分钟：实际对话

```powershell
python test_chat_graph.py
```

依次输入：

1. `酒店附近交通方便吗？`
2. `<酒店库中的完整门店名>，明天入住后天离店，多少钱？`
3. `如果住两晚呢？`
4. `可以再便宜一点吗？`

指出日志中的意图、工具名、日期参数和最终回复。以真实运行结果说明，不预设分类、固定房价或响应时间。

终端商品信息是脚本内置的模拟数据。议价模板强调业务底线，独立查价脚本中的 0.75 系数是另一条演示规则，不应混为真实优惠政策。

### 第 5 分钟：结果与边界

展示会话持久化、Excel 查询结果和工具接口。说明权重需另行准备、网页采集可能失败、RAG 未接入主图及 Docker 尚需适配。

没有独立评测时，用“实现的流程”描述结果，不引用准确率、时延或收益提升数字。

## 可选演示

独立逐晚查询：

```powershell
python query_hotel_price.py 10 12 <完整酒店名>
```

两个数字分别表示距今天的入住 / 离店天数。脚本计算的折扣只是固定系数，跨房型合计不是用户订单总价，输入 `quit` 退出。

平台接入：配置本人闲鱼 Cookie 后运行 `python main.py`，在测试会话发送咨询，再通过卖家发送接管关键词展示人工切换。真实平台测试依赖有效 Cookie 与网络，保留终端演示作为备用。
