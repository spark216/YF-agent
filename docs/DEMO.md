# 5 分钟项目展示

## 准备

安装 `requirements-dev.txt`，启动 `python demo_web.py --redis-simulated`。页面与截图明确标注演示模式，无需生产账号和模型权重。

## 讲解顺序

### 第 1 分钟：业务问题

酒店需求分多轮表达，日期、预算和房型会变化。系统需要结构化状态，而不只是拼接聊天记录。

### 第 2 分钟：架构

展示 README 架构图，说明意图、槽位、校验、检索与回复。Redis 缓存活跃状态，SQLite 保存状态、去重结果和检查点。

### 第 3～4 分钟：实际操作

1. 收集需求，观察缺失条件追问。
2. 补全条件，观察候选与轨迹。
3. 修改预算/房型，观察槽位高亮、版本递增与新候选。
4. 重放上一消息，观察去重且历史不增加。
5. 选择候选，进入预订确认引导。
6. 降低预算，观察无匹配和旧候选清空。

### 第 5 分钟：工程验证

运行 `python -m pytest -q`，讲解并发、缓存回退、工具超时与重启恢复断言。说明当前单进程、真实房态需供应商接口、fakeredis 不等于实际部署 Redis。

## 技术问题

- 条件如何更新？先清空候选与选择、递增版本并持久化，再检索。
- Redis 丢数据怎么办？SQLite 恢复并回填，读取时核对版本。
- 重复消息怎么办？请求结果持久去重，平台另存发送记录；不承诺跨网络 exactly-once。
- 中途重启怎么办？同消息使用同一 thread_id，从持久检查点继续。
- 为什么网页报价不代表有房？酒店目录、参考价与确认库存是不同数据。

可根据代码介绍 LangGraph、多轮槽位、Redis、SQLite 过滤、并发、去重、检查点与追踪。目录实际 9,999 条，建议写“约 1 万家酒店”。
